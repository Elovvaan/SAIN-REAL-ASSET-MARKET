# SRA/BTC platform treasury route

The private Treasury Wallets workstation registers a dedicated SRA-controlled **Bitcoin mainnet receiving address**. Registration records the public address only; it requires **0 BTC** and stores no private key or recovery phrase. With a configured Bitcoin Core RPC, the address can be network-validated. Network validation checks the address, while control remains an administrator declaration until an independent custody check is provided.

The SRA/BTC form prepares exact terms for a live SRA-owned coin listing, a counterparty reference, SRA quantity, BTC quantity, expiry, and the BTC treasury destination. The terms are persisted and auditable. Preparation grants no market execution, reserves no SRA, and does not represent a filled order or acquired BTC. BTC receipt verification uses Bitcoin Core `getrawtransaction` against the recorded receiving address, checks amount, and waits for three confirmations. For historical arbitrary transactions, the Core node needs `-txindex` or a known block hash. A verified BTC receipt stays pending SRA delivery and reconciliation; no BTC treasury balance is inferred from an intent or a transaction ID supplied by a user.

The next connection is a real SRA/BTC counterparty or matching market plus verifiable SRA delivery. The read-only Coinbase feed can inform market observations but is not an execution venue. Customer addresses and platform treasury addresses remain distinct. Bitcoin Core wallet keys stay in the node or dedicated wallet, while RPC credentials are supplied through server environment configuration rather than stored in domain records.
