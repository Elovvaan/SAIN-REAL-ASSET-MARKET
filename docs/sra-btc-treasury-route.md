# SRA/BTC platform treasury route

The private Treasury Wallets workstation registers a dedicated SRA-controlled **Bitcoin mainnet receiving address**. Registration records the public address only; it requires **0 BTC** and stores no private key or recovery phrase. With a configured Bitcoin Core RPC, the address can be network-validated. Network validation checks the address, while control remains an administrator declaration until an independent custody check is provided.

The SRA/BTC form prepares a **market swap request** for a live SRA-owned coin listing, SRA quantity, minimum BTC output, expiry, and the BTC treasury destination. No named bilateral counterparty is required. The request is persisted and auditable in `AWAITING_MARKET_QUOTE`; it has no executable quote, reserves no SRA, and does not represent a filled order or acquired BTC. Bitcoin Core receipt inspection uses `getrawtransaction` against the recorded address, checks amount, and waits for three confirmations. For historical arbitrary transactions, the Core node needs `-txindex` or a known block hash. The trade receipt endpoint requires a verified market execution ID before it can attribute a BTC transfer to a swap; no current route creates that execution state.

The next connection is executable market liquidity for SRA and a route that delivers native BTC to SRA's Bitcoin treasury wallet. A Stellar DEX order book or liquidity pool can exchange Stellar assets when a route exists, but a Stellar BTC representation is distinct from native BTC on the Bitcoin network. Any cross-network conversion must prove the actual native BTC output. The read-only Coinbase feed can inform market observations but is not an execution venue. Customer addresses and platform treasury addresses remain distinct. Bitcoin Core wallet keys stay in the node or dedicated wallet, while RPC credentials are supplied through server environment configuration rather than stored in domain records.
